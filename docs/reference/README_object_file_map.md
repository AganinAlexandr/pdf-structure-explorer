# Object File Map

Этот справочник нужен для связи результатов разбора PDF с внешними данными по объектам.

## Где хранить

Рабочий файл хранится вне репозитория:

- `E:\commons\pdf-structure-explorer\reference\object_file_map.csv`

В репозитории хранятся только:

- шаблон структуры
- описание полей
- скрипт первичного наполнения `scripts/build_object_file_map.py`

## Назначение

Справочник позволяет:

- привязать PDF-файл к объекту
- хранить тип раздела и подраздела
- учитывать случаи, когда один и тот же PDF найден в нескольких каталогах
- связывать экспорт приложения с внешним справочником через `file_name + file_crc32`

## Исключения при сборе

На этапе первичного обхода каталогов некоторые PDF не должны попадать в справочник.

Жёсткое правило на текущем этапе:

- если в имени файла есть `ИУЛ`, такой PDF не включается в `object_file_map`

Причина:

- это не файл раздела, а ИУЛ для раздела
- для текущей аналитики такие файлы не нужны

## Правило идентификации

Основной аналитический ключ:

- `file_name`
- `file_crc32`

Поля пути нужны как служебные и полезны на этапе обхода каталогов, но не должны считаться главным идентификатором файла.

## Рекомендуемая модель строк

Одна строка = одно найденное вхождение файла в каталоге.

Это позволяет:

- видеть все места, где найден файл
- не терять различия по каталогам
- позже при необходимости сворачивать одинаковые файлы по `file_name + file_crc32`

## Поля

- `object_code` — код или номер объекта
- `object_name` — человекочитаемое имя объекта
- `document_role` — роль PDF в наборе файлов, например `section`, `non_section`, `unknown`
- `section_type` — вид раздела
- `section_filter` — нормализованный фильтр раздела для Excel и PQ
- `subsection_type` — вид подраздела
- `subsection_filter` — нормализованный фильтр подраздела для Excel и PQ
- `file_name` — имя PDF-файла
- `file_crc32` — CRC32 файла в верхнем регистре, например `1ADE79D9`
- `source_root` — корневой каталог поиска
- `relative_path` — путь относительно корня поиска
- `full_path` — полный путь к файлу
- `file_size_bytes` — размер файла в байтах
- `last_modified` — дата и время последнего изменения
- `source_catalog_group` — имя набора каталогов или источника
- `is_preferred_source` — признак предпочтительного источника при дубликатах
- `notes` — комментарий

## Использование в Excel / Power Query

Базовая схема:

1. загрузить `object_file_map.csv`
2. загрузить `documents.csv` из выгрузки приложения
3. сделать merge по `file_name` и `file_crc32`
4. дальше расширять `PageSummary`, `ElementsExpanded`, `TablesExpanded` полями объекта

## Рекомендация по фильтрам разделов

Не все PDF являются разделами. Поэтому:

- `document_role` нужно заполнять отдельно
- поля `section_type`, `section_filter`, `subsection_type`, `subsection_filter` заполняются только для PDF, которые реально являются разделами

Желательно хранить два уровня значений:

- исходное человекочитаемое значение в `section_type` и `subsection_type`
- устойчивое нормализованное значение в `section_filter` и `subsection_filter`

Пример:

- `section_type`: `Архитектурные решения`
- `section_filter`: `AR`
- `subsection_type`: `Фасады`
- `subsection_filter`: `facade`

Так будет проще строить фильтры и сводные таблицы в Excel, даже если в исходных именах файлов встречаются разные формулировки одного и того же раздела.

## Рекомендованные значения `document_role`

- `section` — файл является разделом проекта
- `non_section` — файл относится к объекту, но не является разделом
- `unknown` — пока не классифицирован

Примечание:

- файлы, исключённые по правилу `ИУЛ`, в справочник вообще не попадают

## Примечание

Если один и тот же PDF лежит в нескольких каталогах и файл идентичен, строки будут отличаться путями, но совпадут по:

- `file_name`
- `file_crc32`

Именно это и нужно для дальнейшей нормализации в Excel.

## Первичное наполнение

Для первичного построения справочника используется скрипт:

- `E:\repos\pdf-structure-explorer\scripts\build_object_file_map.py`

Что делает скрипт:

- рекурсивно обходит заданные корни
- находит PDF-файлы
- исключает файлы, где в имени есть `ИУЛ`
- вычисляет `file_crc32`
- заполняет технические поля справочника
- сохраняет `source_root`, `relative_path`, `full_path` для последующей нарезки признаков из путей
- помечает `is_preferred_source=true` для одного предпочтительного пути в каждой группе одинаковых файлов по `file_name + file_crc32`

Поля `object_code`, `object_name`, `document_role`, `section_type`, `section_filter`, `subsection_type`, `subsection_filter` после первого прохода можно уточнять отдельно.
